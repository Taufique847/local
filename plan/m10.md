# M10 — BASIC AI VOICE ENGINE

## Complete Master Prompt for Kiro AI

Copy-paste this entire prompt into Kiro:

```text
You are a senior full-stack SaaS architect and AI voice engineer.

You are continuing an existing production-oriented HVAC AI Employee SaaS project.

IMPORTANT:
DO NOT rebuild the existing application.
DO NOT replace existing architecture.
DO NOT create a second backend/frontend architecture.
DO NOT modify unrelated modules.
DO NOT implement M11+ features prematurely.

Your task is ONLY to implement MODULE M10 — BASIC AI VOICE.

==================================================
PROJECT CONTEXT
==================================================

This product is an AI Employee SaaS for US HVAC/home-service businesses.

The platform allows an HVAC business to have an AI receptionist that can answer incoming customer calls.

Current architecture:

Frontend:
- Next.js
- React
- Tailwind CSS
- Responsive dashboard

- Node.js
- Express.js
- MongoDB
- Mongoose

Voice:
- Twilio

- Azure OpenAI

Additional providers:
- OpenAI
- Google Gemini

M9 already established the Twilio phone infrastructure.

Expected high-level call flow:

CUSTOMER
   ↓

Twilio Voice Webhook
   ↓
Node.js / Express Backend
   ↓
Voice Session
   ↓
Azure OpenAI Realtime
   ↓
AI Receptionist
   ↓
Customer

M10 now adds the BASIC AI VOICE CONVERSATION ENGINE.

==================================================
M10 OBJECTIVE
==================================================

Build the first working AI voice receptionist.

The system must be able to:

1. Receive an incoming Twilio call.
2. Initialize an AI voice session.
3. Connect the voice session to the configured LLM provider.
4. Send the customer audio to the AI.
5. Receive AI-generated responses.
6. Convert/stream AI response audio back to the caller.
7. Maintain conversation context during the call.
8. Identify the business/tenant associated with the phone number.
9. Load the business's basic AI configuration.
10. Use an HVAC receptionist system prompt.
11. Log important voice-session events.
12. Gracefully handle errors.
13. End the call cleanly.

M10 is NOT a full AI automation system.

DO NOT implement:
- appointment booking tools
- CRM tool calling
- lead creation tools
- SMS sending
- email sending
- payment tools
- calendar integrations
- human handoff workflows
- advanced knowledge base retrieval
- RAG

- advanced analytics

CORE PRINCIPLE
==================================================

M10 should establish the conversational AI foundation.

M11 will later add AI tools/tool-calling.

Therefore M10 should be designed so tools can be plugged in later without rewriting the voice engine.

- configuration utilities
- Twilio integration

Do NOT treat in-memory sessions as permanent database storage.

- log the issue
- respond with safe fallback
- do not start an AI session

==================================================
STEP 6 — AI RECEPTIONIST SYSTEM PROMPT
==================================================

Create a dedicated prompt builder.

Example:

voicePrompt.service.js

The AI receptionist should behave like:

"You are the professional AI receptionist for an HVAC company."

Behavior:

- answer politely
- speak naturally
- keep responses concise
- ask one question at a time
- understand HVAC-related customer requests
- identify the customer's reason for calling
- collect basic information conversationally
- avoid making unsupported claims
- never invent pricing
- never invent appointment availability
- never claim a booking was completed
- never claim a technician was dispatched
- never claim a payment was processed
- never pretend to have performed an action that has not occurred

The AI can say that it will help collect information and that a team member can follow up when appropriate.

STEP 7 — HVAC CONVERSATION BEHAVIOR

- AC not cooling

- strange noise
- unusual smell
- water leaking
- emergency service request
- maintenance request
- installation inquiry
- replacement inquiry
- general service question

Example:

Customer:
"My AC is running but it's not cooling."

AI:
"I'm sorry you're dealing with that. I can help get the details. Is the system blowing air but the air isn't getting cold?"

The AI should continue naturally.

Do NOT turn the call into a rigid questionnaire.
```

Tumhare current module sequence mein:

| Module  | Main responsibility         |
| ------- | --------------------------- |
| **M9**  | Twilio Phone Infrastructure |
| **M10** | **Basic AI Voice ← ab ye**  |
| **M11** | AI Tools / Tool Calling     |
| **M12** | Lead Automation             |
| **M13** | Appointment Automation      |
| **M14** | SMS Automation              |
| **M15** | Call Logs + Transcript      |
| **M16** | AI Employee Configuration   |
| **M17** | Knowledge Base              |
| **M18** | Human Handoff               |
| **M19** | Billing + Usage             |
| **M20** | Production + Security       |

Is sequence ka important point ye hai ki **M10 ke end par AI customer se actual voice conversation kar sakega, lekin abhi AI ko appointment book karne ya lead create karne ka authority nahi dena hai.** Tool-calling M11 mein aayega.

**M10 ka practical result:** customer HVAC number par call karega → Twilio → tumhara Node backend → Azure OpenAI Realtime → AI receptionist customer se baat karega → voice response Twilio ke through customer ko milega.
