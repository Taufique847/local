# 4. FIELD DEFINITIONS

## businessId

Required.

Every appointment belongs to exactly one business.

Never trust a frontend-provided businessId.

Derive ownership from the authenticated user.

---

## customerId

Required.

References Customer.

The customer MUST belong to the same business.

Reject cross-business customer references.

---

## leadId

Optional.

References Lead.

If provided:

* Lead must belong to same business.
* Lead's customer should match customerId.

Do not require every appointment to have a lead.

---

## serviceId

Required.

References Service.

Service must belong to same business.

Normally only active services should be selectable for NEW appointments.

Existing historical appointments must remain valid if a service later becomes inactive.

---

## title

Optional or automatically generated.

Example:

```text
AC Repair — John Smith
```

If the system automatically generates it, make it editable where useful.

Do not duplicate information unnecessarily.

---

## description

Optional.

Example:

```text
Customer reports AC blowing warm air.
```

# 13. SLOT GENERATION

# 14. EXISTING APPOINTMENT CONFLICTS

If:

```text
10:00–11:30
```

is already booked,

a new appointment must not overlap.

Reject:

```text
09:30–10:30
10:30–12:00
10:00–11:00
11:00–12:00
```

depending on exact overlap.

A valid appointment:

```text
11:30–13:00
```

can start immediately after the previous appointment if the scheduling rules permit.

Use proper interval-overlap logic.

Do not rely only on frontend validation.

# 15. DOUBLE-BOOKING PROTECTION

This is a critical backend requirement.

The backend MUST validate availability again when creating an appointment.

Do NOT trust the frontend's available slot.

Flow:

```text
Frontend selects 10:00
        ↓
POST create appointment
        ↓
Backend checks business hours
        ↓
Backend checks existing appointments
        ↓
Backend checks service duration
        ↓
Backend confirms slot
        ↓
Create appointment
```

If another booking has already taken the slot:

Return a conflict response such as:

```text
409 Conflict
```

Example:

```text
This appointment time is no longer available.
Please select another time.
```
