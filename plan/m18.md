# 6. Sabse important rule: M18 akela decision nahi karega

Final architecture:

```text
                 AI
                  │
                  ▼
             M11 Tool
                  │
                  ▼
              M11.2
                  │
                  ▼
          ┌───────────────┐
          │ M18 Policy    │
          │ Guard         │
          └───────┬───────┘
                  │
              ALLOWED?
             /         \
           NO           YES
           │             │
        Reject       Operational
                     Module
                       │
             ┌─────────┼─────────┐
             ▼         ▼         ▼
            M12       M13       M14
           Leads   Appointment   SMS
```

Example appointment:

```text
M18 = booking allowed
        +
M13 = slot actually available
        +
confirmation = valid
        ↓
BOOK APPOINTMENT
```

Agar **M18 allow kare but M13 slot unavailable ho**, booking nahi hogi.

Similarly:

```text
M18 = SMS allowed
+
M14 = consent + provider + destination valid
        ↓
SEND SMS
```

# 7. Default policy

New HVAC business onboard hone par sensible default policy:

```text
AI = Enabled

Business-specific claims = Knowledge required

AI booking = Enabled

Customer confirmation = Required

After-hours = Emergency only

Emergency escalation = Enabled

Exact pricing = Restricted

Starting pricing = Allowed

AI SMS = Allowed

Customer opt-out = Always respected

Credential collection = Blocked

Payment-card collection = Blocked

Sensitive actions = Fail closed

Tool policy = Allow-list

Human handoff = Enabled
```

Ye **M18 ka baseline configuration** hoga; individual business onboarding ke through values change ki ja sakti hain.

### Ek important correction

M18 me `business hours`, `service area`, `pricing`, etc. ka **duplicate source of truth** mat banao. Jahan M13/M14/M17 ya Business Settings me already authoritative data hai, M18 ko **policy/permission layer** rakhna hai.

For example:

* **M13:** actual appointment availability
* **M14:** actual SMS consent/delivery
* **M17:** business knowledge
* **M18:** AI ko kya allowed hai
* **M16:** customer identity/data
* **M15:** kya actually hua

Yahi separation tumhare final SaaS ko scalable aur maintainable rakhega.
